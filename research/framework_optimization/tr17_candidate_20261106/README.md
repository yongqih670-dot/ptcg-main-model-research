## 已交付的优化

最新隔离源码同时保留 baseline、candidate 和控制链。候选开关默认关闭，涵盖动作映射与回放布局缓存、序列索引、outbox 索引、checkpoint 引用计划、参考核心参数传输、恢复事务、不可变 staging 和归档 delta 传输。完整源码与基线/候选差异继续保留在项目本地，未随这次结果同步公开。这些实现的存在不等于端到端提速已达标。

日志与归档链采用有界诊断输出、压缩落盘和容量预测；连接链采用复用已认证连接、串行业务请求、有限次数的认证前间隔重试。V20 实测使用 1 个已认证连接、5 个串行请求、0 次重试，完成 V18 原件及独立回放核验。V23 失败后的原件封存使用 1 个已认证连接、28 个串行请求；封存补完不能把失败案例改为有效对照。

V24 源码补入正式入口的项目依赖 bootstrap、显式 CPU-only 范围、共用原件校验/计时/清理组件，以及按 PID 和出生身份核对的子进程树回收。开发检查覆盖真实已留存 manifest/ACK/原件的完整 SHA 验证、真实子进程读写及退出、缺文件/错 SHA/错 ACK/缺终态/主错误伴随清理错误五类合成负例、拒绝 GPU 能力和受影响的 Session 回归。合成负例不是 GPU、PPO 或冷恢复通过证据。
