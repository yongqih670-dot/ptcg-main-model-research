当前项目目录没有 Git。工作范围为 research/framework_optimization/，建议使用 source/、tests/、benchmarks/、reports/、patches/ 子目录。基线源码只复制必要文件，记录路径及 SHA256；大模型与归档保持只读引用，禁止完整复制 runs 或环境。现用 ptcg_lab/、scripts/、configs/、研究账本和已归档 run 保持不变。候选通过独立包、显式入口或补丁交付；不得让现用默认导入意外加载候选实现。发现主线源码变化时复核基线差异，不能覆盖他人更新。

服务器重工程验收仍须唯一研究控制器的现行受控入口、明确工程票据和预算预留；当前任务不另设调度器、不签发科学 raw、不竞争权威账本。没有工程槽位时，继续实现、轻量测试和生成验收命令，把硬件实测标为待执行，不能伪造加速比或无限等待。需要集成时交付具体补丁和资源需求，不以笼统询问阻塞前期工作。

## 3. 目标与衡量方法

主指标：相同输入、PPO 配置和资源约束下，端到端实际唯一成功优化决策/秒，以及每万决策作业墙钟、CPU/GPU 成本。采样 decisions/s、BO3/s、更新耗时、GPU 活跃区间、峰值内存/显存、写入与传输字节、归档队列大小和等待时间为解释性指标。

工程优化保持观测可见性、合法动作支持、条件概率、完整 BO3 边界、策略版本和唯一决策计数正确。优化器逻辑、训练样本量、对手和 PPO 超参数不能随性能实验一起变化。minibatch=256 保持为科学基线；更大推理 microbatch 与更大 PPO minibatch 必须区分。

目标是取得可复核的端到端改善；首阶段以 >=20% 改善作为工程争取目标，不是已获收益或强制筛选阈值。没有收益、误差过大或测量噪声过高的选项保留为关闭/淘汰并报告。吞吐提升不代表模型棋力提升。

## 4. 分阶段实施

### M0：建立可运行基线与计时闭环（先做）

1. 建立最小源码快照和输入哈希 manifest，检查项目独立 Python 环境、依赖版本与可用测试；不改系统或共享环境。
2. 实现离线日志分析器和候选路径的分阶段计时：初始化/恢复、环境推进、特征编码、策略推理、IPC、数据整理、H2D、PPO 前向/反向/step、一致性校验、checkpoint 序列化/写入/hash、压缩/传输/ACK、共享 GPU 等待、背压、收尾。
3. 以墙钟关键路径与资源活动分别计量，重叠区间不能相加当墙钟；报告残余未解释时间。CUDA 微基准用 events 或明确同步边界，不能仅用异步提交的 Python 时长。短窗口 profiler 只在候选中启用，测量自身开销。
4. 先从现有完整 run 提取基线，缺少的字段记 unknown。形成 reports/baseline.json 与可读说明，不用推测补数。

### M1：I/O、归档与连续运行可靠性

1. 按 M0 结果排优先级。识别重复序列化、重复全文件扫描/hash、碎片化传输和不必要的同步等待，复用已验证且输入未变的不可变对象。
2. 候选实现有界生产者/消费者队列、批量清单/传输与背压；限速和队列上限保持可配置但默认不扩大现有授权。
3. 保存时必须冻结完整一致的状态；后台序列化不能持有仍被 optimizer 修改的张量引用。完整 ACK、引用计数和两个恢复点的删除条件保留。不得靠删除安全屏障获得加速。
4. 用可控故障测试覆盖断网、半包、重复 ACK、进程退出、PID 复用、恢复点轮换与未训练尾部；恢复后不得丢失/重复计数。当前控制器退出问题先基于日志定位，再提交修复，不能预设根因。

### M2：数据批处理与 Python 开销

1. 将 rollout 的特征、mask/mapping、条件子步偏移、old_logp/value、advantage/return 整理为批量数据结构，减少重复 numpy concatenate、CPU/GPU 拷贝和逐样本标量同步。
2. 对条件动作分组归一化与 log-prob/entropy 汇总实现向量化；保留 >63 候选、完整原始索引、唯一 STOP、可变子步和动作序列的正确语义。
3. 仅在实测有收益时引入 pinned memory、non_blocking 和有限双缓冲；分别验证异步生命周期和数据不被提前复用。不要无条件打开所有优化开关。
4. 保持 PPO 样本次序、epoch/minibatch 边界与 KL 提前停止口径；用同一离线 fixture 比较输出、梯度和更新。

### M3：并行环境与 CPU/GPU 协同

1. 实现可配置多环境采样协调器（先比较 1/2/3 环境），总 CPU 额度内重新分配各进程 torch/BLAS 线程，防止线程超额争抢。
2. 多环境共享同一冻结 policy version；按待推理请求合成 microbatch。每个 BO3 的席位、对手、cursor、RNG 与 pending 状态可恢复，输出具有确定的身份和汇总顺序。
3. 先允许环境推进/数据准备/归档与计算重叠。更新下一版本前维持明确策略版本屏障；不能在 GPU 更新时无约束采集旧策略数据并作为新策略的 on-policy batch。
4. 真正异步 actor-learner 或允许策略滞后的算法另立未来提案，不能宣称与当前 PPO 完全等价。native 环境未暴露 seed，不承诺整局逐字节配对复现。

### M4：混合精度与算子优化

1. 增加默认关闭的 precision 配置：FP32 基线、硬件支持时 BF16 autocast、FP16 autocast + GradScaler；不得直接全模型 half()。
2. 对网络线性/attention 计算尝试 AMP，敏感的 log-prob、ratio、归一化和统计保留适当高精度。保留原 master weights/optimizer 契约；新增 scaler 等状态必须纳入完整 checkpoint/恢复。
3. 同一固定模型和真实轨迹 fixture 比较 log-prob/value、loss、梯度、KL、NaN/Inf、clip 和 early-stop 决策；速度与显存单独报告。
4. 现行 CPU/GPU log-prob 1e-4、value 2e-4 阈值不放宽。AMP 未通过则不得接入当前训练，可交付关闭的实验后端并报告原因。
5. TF32、torch.compile、fused optimizer 等仅在 profiling 指向相关瓶颈后单独测试，区分编译/预热成本和稳定区间，不同时修改多个开关后归因。

## 5. 验收与预算

- 数值/映射单测：普通与超长候选、STOP、可变条件序列、混合长度和完整 BO3；CPU/GPU 差异按现行阈值。FP32 路径验证 loss、梯度和优化器状态；允许误差应在测量前写明，不能事后扩大。
- 恢复验收：actor/critic/optimizer/全部 RNG/worker cursor/pending/league/新增精度状态完整；在 checkpoint、ACK、更新提交边界故障注入，核对无丢失和无重复计数。
- 性能比较：同输入哈希、同硬件/线程额度、同配置，先短预热，按 300–600 秒有界窗口和噪声选择重复次数；报告样本数、中位数和波动。官方环境无法固定 seed 的对局测量与固定轨迹回放基准分开。不得预先承诺倍数或完成小时数。
- 首轮优先已有日志、离线 fixtures 与轻量本地测试，不在本机启动科学 PPO 训练。服务器验收单项最多 1800 秒，原预算和硬时限若更紧则服从更紧值；没有票据不启动。
- 服务器沿用单张启动时空闲的授权 GPU4–7、优先6/7、共享保护，初始3CPU/32GiB并服从实时每GPU份额；所有子进程同一限额。仅原HDD2专属根可写，HDD1只读。不得sudo或修改共享环境。
- 本地/服务器总工作集及空闲下限沿用现行 policy，禁止复制大规模训练目录消耗额度；复用完整归档，仅验证变化输入。
- 不启动第二个重任务、不更改当前 TR12 配置/归档引用/科学量账本、不占用受保护的最终预算。工程耗时如实记录并在受控验收时按现行口径入账。
